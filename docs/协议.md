# 协议

三块：**框架 ↔ 服务端**（OneBot v11）、**面板 → 服务端**（注入口）、**服务端 → 面板**（回话口）。

发布版的产品边界是：**QQ 式客户端核心不以 OneBot 为内部数据格式**。
OneBot 只在 `server/` 与 `panel/connectors/onebot.py` 这一层转换；客户端内部统一使用
`panel/core/` 的消息、事件、资料和连接状态模型。`/say` 仍保留作本地旧版回调兼容，
不作为云端长期协议。

```
                    ┌──────────────── onebot-local ────────────────┐
                    │                                              │
 面板 ──POST /__inject──→  转成 message 事件 ──WS──→  框架          │
 面板 ←─POST /say──────   转成动作调用   ←──WS──  按 send_private_msg │
                    │                                              │
                    └──────────────────────────────────────────────┘
```

## 端口

| 口 | 协议 | 干什么 |
|---|---|---|
| 3000 | HTTP | 动作调用、注入口 `/__inject`、状态 `/__state` |
| 3001 | WebSocket | 框架连这个，收事件、发动作 |

两个口都只绑 `127.0.0.1`（`listen` 可改）。改端口见 `server/config.json`。

## 鉴权

`token` 留空时仅建议本机使用。填了之后，HTTP 请求和 WebSocket 握手均须鉴权：

```
Authorization: Bearer <token>
```

或者 URL 上：

```
http://127.0.0.1:3000/__state?access_token=<token>
```

带错回 `401`。WebSocket 连接可以通过 `access_token` 查询参数携带令牌；服务端拒绝网页发起的 WebSocket 连接。服务端回调面板时使用 `Authorization` 请求头。

## 框架 ↔ 服务端：OneBot v11

### 事件（服务端 → 框架，走 WebSocket）

用户说了一句话，服务端推一个标准的私聊消息事件：

```json
{
  "post_type": "message",
  "message_type": "private",
  "sub_type": "friend",
  "self_id": 10000,
  "user_id": 10001,
  "message_id": 1001,
  "message": [{ "type": "text", "data": { "text": "在吗" } }],
  "raw_message": "在吗",
  "font": 0,
  "sender": { "user_id": 10001, "nickname": "本地用户" },
  "time": 1762500000
}
```

图片是先把 base64 落成文件，事件里只写文件名：

```json
{ "type": "image", "data": { "file": "m1a2b3c4.png", "sub_type": 1 } }
```

**为什么这样**：桥接类框架对 `file` 字段有校验，只认「简单文件名」（不能带斜杠、不能带 `base64://`），否则图会被丢掉。所以必须先落盘，等框架来 `get_image` 取。

心跳每 30 秒一次（`heartbeatMs` 可调）：

```json
{ "post_type": "meta_event", "meta_event_type": "heartbeat",
  "self_id": 10000, "status": { "online": true, "good": true },
  "time": 1762500000, "interval": 30000 }
```

框架有「上游健康检查」的时候，没这个心跳会被判掉线、一直刷警告。

### 动作（框架 → 服务端，走 WebSocket 文本帧）

请求：

```json
{ "action": "send_private_msg", "params": { "message": "我回来了" }, "echo": "a1" }
```

成功：

```json
{ "status": "ok", "retcode": 0, "data": { "message_id": 1002 }, "echo": "a1" }
```

不支持的动作用 `retcode: 1404` 明确拒绝，**不会假装成功**：

```json
{ "status": "failed", "retcode": 1404, "data": null, "echo": "a1" }
```

### 动作（框架 → 服务端，也可以走 HTTP）

两种发法都认：

```
POST /send_private_msg          body 就是参数
POST /                          body 是 {action, params, echo}
```

返回形状跟 WebSocket 一样。

### 支持哪些动作

| 动作 | 说明 |
|---|---|
| `get_login_info` | `{user_id, nickname}` |
| `get_status` | 永远 `{online: true, good: true}` |
| `get_version_info` | 报自己是 `onebot-local` |
| `can_send_image` / `can_send_record` | 都是 `{yes: true}` |
| `get_friend_list` | 只有一个人，就是 `peerId` |
| `get_stranger_info` | 同上 |
| `send_private_msg` / `send_private_message` / `send_msg` | 把话推给面板 |
| `get_image` | 读 `mediaDir` 里那个文件，回 base64 |
| `get_group_list` | 永远空数组 |
| `get_forward_msg` / `get_recent_messages` / `get_unread_messages` | 空结果 |
| 其它 | `1404` |

## 面板 → 服务端：注入口

```
POST http://127.0.0.1:3000/__inject
Content-Type: application/json

{ "text": "在吗" }
```

带图：

```json
{ "text": "看这个", "图": [ { "b64": "iVBORw0…", "name": "shot.png" } ] }
```

返回：

```json
{ "ok": true, "accepted": true, "pushed": 1, "message_id": "client-message-id", "event_id": "client-event-id" }
```

客户端须提供 `message_id`、`event_id` 和 `conversation_id`，重试原样使用同一身份。
回执另含 `delivery_status`：`framework_waiting` 或 `framework_unknown`。
`pushed` 仅用于兼容诊断，不是框架接收确认；`0` 时持久排队，框架连接后尝试发送。
事件在网络写入前先持久化为结果未知；已经尝试写入的事件在断线、重连和重启后均不自动重放。
Node socket 的背压返回 `false` 表示已缓冲，也按结果未知处理。确定不可写的 socket 保留排队；
保存失败返回错误，不计为成功。当前 OneBot v11 无事件处理确认，不能据此声称框架已接收或 DSH 已处理。
假端将端点 UUID、单调编号、注入幂等表和待回调队列保存在自己的数据目录，重启不重新从 1000 计数。
`POST /__delivery` 按原会话、消息、事件身份查询已保存投递状态，不发送消息；
`/__state.pending` 区分等待框架和处理结果未知的条数。

## 服务端 → 面板：回话口

OneBot 模式在面板配置中固定端口为 8610，服务端收到 `send_private_msg` 就往这儿 POST：

```
POST http://127.0.0.1:8610/say
Content-Type: application/json

{
  "text": "她说的原话",
  "段": [
    { "type": "text",  "text": "她说的原话" },
    { "type": "image", "mime": "image/png", "b64": "iVBORw0…" },
    { "type": "record","mime": "audio/mpeg", "b64": "SUQzB…" }
  ]
}
```

`段` 里每一段都可能是：

- `text`：文字
- `image`：`b64` + `mime`，或者 `url`
- `record`：同上（语音；有同名 mp3 时会自动换成 mp3，因为 silk 浏览器播不了）
- `face`：`id`

回调同时包含稳定 `message_id`、`event_id`、`sequence`、`conversation_id`、原始时间及发送者。
面板本地保存成功后返回 `{ok:true,message_id,event_id}`；假端校验身份后才移出持久队列。
确认失败会按原身份重放。配了 token 时在请求头中带 `Authorization: Bearer <token>`。

客户端、网关及假端的 `media_limits` 默认图片 10485760 字节、语音 20971520 字节，
分别可配置为 1 到 52428800 之间的整数。握手和假端状态接口公布 `media_limits`；
网关公布其配置与假端能力中的较小值，客户端再取自身发送配置与网关公布值的较小值。
旧网关缺少该字段时兼容为 512 KiB，旧假端兼容为 2 MiB，不假设旧服务支持更大附件。
网关及假端请求体最大为 `4*ceil(max(image,record)/3) + 1 MiB`，包含 base64 和封套；
WebSocket 帧同样有界。多附件总量仍须在请求体限制内。
原图、音频原样保存和传输，缩略图单独生成；下载按网关公布的类型上限有界读取并核对 SHA-256。
媒体超限返回 `413`、`error_code: media_too_large`、`retryable: false` 和可读原因。
明确的内容拒绝（400/413/415/422 且 `retryable:false`）使回调进入持久的 `rejected` 状态，
保留原始段、消息/事件/会话身份、时间、尝试次数与错误；其他可投递回调继续处理。
暂时无法连接、回执丢失或身份不符仍为 `pending`，沿原身份按 2 到 30 秒间隔退避重试。
`/__state.pending.callbacks` 与 `rejected_callbacks` 分开计数；拒绝记录不会自动删除或自动重放。

鉴权的 `GET /__callbacks` 返回 `items`，每项含 `metadata`、`status`、`attempts`、
`last_error`、`next_attempt_at`，不返回媒体正文。
鉴权的 `POST /__callbacks/retry` 接受 `{event_id}`，只将保留的那条回调重置为待尝试，
回执 `callback_pending` 仅表示重试状态已落盘。消息身份与原始时间保持不变；
原因未排除时会再次被拒绝。此操作不重放用户输入，不重新调用框架或模型。

## 状态查询

```
GET http://127.0.0.1:3000/__state
```

```json
{
  "ok": true,
  "selfId": 10000,
  "peerId": 10001,
  "connections": 1,
  "messageId": 1002,
  "actions": [["send_private_msg", 3], ["get_image", 1]]
}
```

`connections` 是现在有几个框架连着，面板用它显示「等框架 / 已连上」。
`actions` 是调用统计，排查「框架到底调了什么」很有用。

## 一次完整的来回

1. 你在面板打字：「在吗」
2. 面板 `POST /__inject {text:"在吗"}`
3. 服务端推 `message` 事件给框架
4. 框架把这句话交给 AI，等回复
5. AI 回「我在」，框架调 `send_private_msg {message:"我在"}`
6. 服务端把它整理成 `{text, 段}`，`POST http://127.0.0.1:8610/say`
7. 面板收到，画成气泡

## 客户端内部统一事件

所有连接器都要转换成下面的字段；字段名稳定后，界面不需要判断 OneBot、DSH 本地或远程：

```json
{
  "conversation_id": "main",
  "message_id": "msg_xxx",
  "event_id": "evt_xxx",
  "sequence": 42,
  "sender": {"profile_id": "peer", "name": "合成对方"},
  "created_at": 1762500000.0,
  "delivery_status": "delivered",
  "segments": [{"type": "text", "text": "你好"}],
  "attachments": [{"media_id": "m_xxx", "url": "/media/m_xxx"}],
  "capabilities": {"text": true, "media_ids": true},
  "protocol_version": "dsh-client/1"
}
```

`message_id` 是消息稳定标识，`event_id` 是传输事件标识；重连时以二者去重，不能只按
文字内容去重。`sequence` 保存来源的远端接收序号，`local_sequence`/旧 `序号` 负责本地排序和分页；
二者互不推进，发送消息没有接收序号。媒体正文归档后只
保留 `media_id` 和临时 URL，不把大段 base64 写回聊天记录。
图片和语音（`image` / `record`）都走同一套媒体归档路径，聊天记录只保存媒体 ID、类型和可续期的本地 URL。

## 连接状态

界面显示的状态至少区分：

| `phase` | 含义 |
|---|---|
| `disabled` | 配置存在但连接器未启用 |
| `configured` | 已填配置，尚未确认连通 |
| `connecting` | 正在握手或重连 |
| `connected` | 已完成握手并可收发 |
| `degraded` | 可用但能力受限，例如单轮模型适配器 |
| `disconnected` | 对端明确断开或没有框架连接 |
| `error` | 连接或协议错误 |
| `endpoint_changed` | 网关数据身份改变，暂停投递，需明确重新绑定 |

“已启用”不能直接画成“在线”。

## 本项目网关协议

`server/gateway.py` 和 `panel/connectors/remote.py` 实现 `dsh-client/1`。
这是本项目网关，不能填写原生 DSH 地址使用。网关连接独立 OneBot 假端，DSH 与 qqbridge 的职责不变。
当前只实现客户端主动 HTTP(S) 轮询；没有实现 WebSocket/WSS。
网关 HTTP/TLS 监听仅绑定回环；跨机联调采用独立 SSH 回环转发，未建立公开互联网入口。

| 接口 | 作用 |
|---|---|
| `POST /v1/handshake` | 请求必须是 `dsh-client/1`，返回明确 `ok:true`、`hello_ack`、端点身份、`http_poll`、资料和能力 |
| `POST /v1/messages` | 保存稳定身份的发送记录；相同身份/内容重试返回原确认，身份与内容冲突拒绝 |
| `POST /v1/message-status` | 校验端点、会话、消息和事件后查询投递进度；查询不重新发送 |
| `GET /v1/events?resume_from=N` | 按网关接收序列重放最多 100 条事件，读取本身不提交游标或去重 |
| `POST /v1/acks` | 对已持久化事件明确确认，检查端点、会话、消息、事件和序号 |
| `POST /v1/heartbeat` | 独立心跳并报告框架连接情况 |
| `POST /v1/media` | 上传有效类型上限内的媒体正文和 SHA-256，返回网关媒体 ID |
| `GET /v1/media/<id>` | 为媒体重新签发 60 秒临时下载引用 |
| `GET /v1/media-content/<id>` | 校验认证、有效期和签名后返回内容，客户端再校验哈希和大小 |

所有请求均校验独立 Bearer token；客户端拒绝跨地址重定向。
HTTPS 使用默认严格证书和主机名校验，可用独立 `ca_file` 信任测试 CA，不修改系统信任库。
HTTP 只有显式允许的回环测试可使用；临时 SSH 隧道只是运输路径。
`test_controls` 默认关闭；开启时才提供只作用于该隔离网关的故障注入和合成统计接口。

### 持久化与回执

1. 发送前将统一模型写入原 JSONL 并 fsync，建立发送索引，状态为 `saved`（客户端已保存）。
2. 网络前持久记录 `unknown`，网络异常或回执缺失、错误对象、身份不符都不能报告成功。
3. 正确网关回执转为 `gateway_accepted`；状态查询可更新为 `framework_waiting`（等待框架）
   或 `framework_unknown`（尝试写入，处理未知）。只有明确协商了应用层回执才可使用 `framework_accepted`。
   当前假端/网关没有端到端 DSH 或框架处理回执，故不声明 `delivery_receipts`。
4. `failed` 用于确定未发出的准备失败；`unknown` 只能向声明 `idempotent_send` 的端点沿用原身份重试。
5. 接收先归档媒体、写 JSONL 并 fsync，再提交范围为端点+会话+方向的去重索引。
6. 保存失败不确认。确认失败保留记录并允许重放，重复事件重新确认，确认成功后才提交持久游标。
7. 重启时从 JSONL 恢复索引，并恢复已提交游标；每次接收不再全量扫描历史。

发送状态查询在独立任务中进行，网络等待不占用收发锁。每次最多查询一条仍可能推进的记录，
同一条至少间隔两秒；按最早查询时间轮转，端点身份筛选发生在取限额之前。
未协商应用层确认时，`framework_unknown` 不参与状态查询，历史中的旧记录不会持续占据查询名额。
排队消息仍会推进到处理未知，且始终不据此声称 DSH 已处理。

发送请求携带握手得到的真实网关 `endpoint_id`，网关拒绝错投到其它身份。
消息另外保存 `remote_endpoint_id`，接收索引和游标以配置端点 + 真实网关身份分隔，兼容迁入旧游标。
网关身份变化时进入 `endpoint_changed`，从「控制台 → 聊天连接」重新绑定。重新绑定需要提供当前观察到的身份，
保留历史及旧游标，建立新命名空间；旧端点的待发/未知记录不会自动转投。
控制台通过本地面板 RPC `rebind_endpoint(observed_endpoint_id)` 完成绑定。

内部 `protocol_version` 固定为 `dsh-client/1`，`source_protocol_version` 保留原始来源协议，
`transport_protocol_version` 记录网关运输版本。来源发送者、时间、端点和远端序号保留在记录中。
接收和发送身份独立；OneBot 的机器人 `selfId` 是客户端的对方，用户 `peerId` 是客户端的我。
资料逐字段按 DSH > OneBot/qqbridge > 本地配置合并，默认值不覆盖已有昵称，查询不会伪造活动时间。
能力只声明实际已实现并协商的项目，未提供的能力不能默认为开启。

网关和假端保存自己的独立媒体，客户端与远端媒体 ID 有持久映射；临时 URL 不写入聊天历史。
`MemoryRemoteTransport` 只用于内存故障测试；真实网络、浏览器、隧道和 HTTPS 必须分别验收。
